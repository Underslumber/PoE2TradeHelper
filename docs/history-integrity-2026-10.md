# Целостность истории цен — 0.2.113

Проверка продолжает аудит версии 0.2.112. Область: наблюдения цен, хранение и сжатие истории, графики, валютный анализ и историческая оценка сделок. Новые внешние источники не подключались.

## Подтверждённые ошибки и изменения

| Область | Ошибка | Исправление |
|---|---|---|
| История ItemBases | Сохранённые цены непросканированных основ записывались с новым временем | В историю передаются только новые наблюдения; сохранённые строки остаются для UI |
| Компактизация | Разные источники усреднялись и получали имя последнего источника | Источники и уровни детализации разделены при чтении; агрегаты группируются по источнику |
| Повтор записи | Один raw-снимок мог несколько раз увеличивать вес среднего | Проверка идентичности наблюдения в транзакции; точные raw-дубли исключаются из агрегации |
| Числовые данные | Бесконечные значения могли сохраниться или оборвать запись | Неконечные значения отбрасываются, дробная активность и отрицательное изменение сохраняются |
| Графики | Успешный результат и временная ошибка кэшировались бессрочно | Обновление по ревизии снимка и сроку кэша, повтор после ошибки |
| Валютный анализ | Нулевое изменение заменялось внешним значением; SQLite блокировал async-запрос | Явная проверка отсутствующего значения; чтение вне event loop |
| Исторический benchmark | Для прошлого входа мог использоваться будущий курс; состав корзины менялся при пропусках | Только предшествующие наблюдения; численная оценка корзины требует полного состава |
| Фоновый сбор | Явная категория ItemBases и отдельный сбор могли запускаться вместе | При включённом отдельном сборе общий маршрут исключает эту категорию |
| Legacy JSONL | Глобальная максимальная дата SQLite скрывала пропущенные старые записи | Завершённость переноса связана с конкретным файлом и хранится в той же БД; нечисловые значения фильтруются |
| Уведомления | Неуспешная отправка обновляла базовую цену и теряла пересечение порога | После HTTP-сбоя базовая цена сохраняется для следующей попытки |
| Проверка сигналов | Последующая цена могла относиться к другому источнику или валюте | Сравниваются только совместимые снимки |

## Границы

Опубликованный сервер не обновлялся. При одном тестовом прогоне из-за отсутствовавшей изоляции в локальную SQLite попали служебный checkpoint тестовой лиги и один снимок публичного FunPay (2148 офферов). Эти конкретные строки сохранены отдельно и удалены транзакционно; 124798 строк market_history при устранении последствий не менялись. Правил Telegram в базе нет. Тестовый conftest теперь назначает временные DATA_DIR/STORAGE_DIR/SQLITE_PATH, отключает .env и фоновые сборщики до импорта приложения. Исправления не восстанавливают автоматически уже смешанные агрегаты или записи со старой ценой и новым временем: без исходных наблюдений нельзя достоверно восстановить происхождение и время. Автоматическая очистка таких данных не выполняется.

Повтор raw-наблюдения распознаётся, пока исходные записи доступны. Повторная загрузка старого payload после его компактизации не имеет гарантии дедупликации: агрегат не содержит идентификаторов всех исходных наблюдений. Поздние новые наблюдения нельзя просто отбрасывать по наличию агрегата.

При совпадении старой JSONL-строки с уже сжатым бакетом её вклад невозможно установить. Автоимпорт пропускает такую неоднозначную строку, не меняет агрегат и сохраняет число пропусков в маркере завершения. Это предотвращает повторный учёт, но не доказывает полноту старых данных.

При неполной корзине benchmark результат становится недоступным, а сведения о недостающих компонентах сохраняются. Это предотвращает искусственное изменение доходности из-за изменения состава корзины. Уведомление после сетевого сбоя может быть отправлено повторно, если Telegram принял сообщение, но ответ был потерян: внешнее подтверждение доставки не обладает транзакционной связью с локальной SQLite.
