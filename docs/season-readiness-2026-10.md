Рекомендуемый фокус проекта: накопленная история, объяснимые сигналы, портфель и фактический P/L. Копирование внешних таблиц цен даёт меньше пользы, чем сравнение источников, свежести и исполненных собственных сделок.

## Актуальность источников

Живые GET к trade2 leagues и poe.ninja economy leagues вернули HTTP 200. В обоих есть `Forbidden Rites`, `Runes of Aldur`, их HC-варианты и постоянные лиги. У trade2 первой идёт `Forbidden Rites`. Это подтверждает нынешний список, но не дату или название будущего сезона. Непроверенный будущий сезон в код не зашит.

EN/RU `trade2/data/static` вернули по 15 категорий. `poe.ninja` Currency для `Forbidden Rites` вернул 51 строку, `core.primary=divine`, ETag и фактический `Cache-Control: max-age=1800`. Следовать заголовку конкретного ответа, а не фиксировать в коде приблизительные 5 минут из документации. Эти пробы проверяют доступность и форму ответов; полноценные search/fetch и сделки не выполнялись.

[Документация GGG](https://www.pathofexile.com/developer/docs) отдельно описывает поддерживаемые API, OAuth и динамические лимиты; веб-trade2 нельзя обещать как стабильный официальный developer contract. [Справочник GGG](https://www.pathofexile.com/developer/docs/reference) всё ещё помечает Account/Public Stashes как PoE1 only. Не планировать сезонную функциональность вокруг непроверенного приватного stash API PoE2.

У poe.ninja публично разрешён economy surface без SLA; builds/profiles не предназначены для стороннего использования. Не подключать такие внутренние endpoints ради автоматической меты. Текущий приоритет каталога основ — эвристика проекта, которую надо пересмотреть по подтверждённой мете нового сезона.

## План запуска

| Этап | Действие | Критерий приёмки |
|---|---|---|
| До патча | Сохранить backup SQLite штатным online backup, `.env` отдельно; проверить восстановление в отдельный путь | Восстановленная копия открывается, таблицы/строки присутствуют; не копировать одну live DB без WAL |
| До патча | Сопоставить локальные правки с актуальным main, сохранить пользовательские изменения | Нет потерянных CLI/currency-target изменений; однозначная версия релиза |
| Перед стартом | Проверить `USER_AGENT`, исходящую сеть, trusted public origin и SMTP | Реальная регистрация доставляет письмо с нужным HTTPS URL, cookie Secure, токен не раскрывается удалённому клиенту |
| После анонса | Установить точный старт UTC, сверить новую лигу и категории | Статус сборщика показывает нужный league и интервал, а не дату старой лиги |
| На старте | Дождаться первых Currency и основных категорий | `created_ts` растёт в SQLite для новой лиги, цены не взяты из старой; ошибки видны отдельно |
| На старте | Проверить RU/EN, выбранную лигу и валюту в браузере | Нет смешения языков, бесконечного loading, принудительного частого внешнего polling |
| После первых данных | Проверить точный поиск основы и похожий рынок одного предмета | Есть реальные priced listings с валютой и достаточным контекстом; агрегат не выдан за точную цену |
| После первых данных | Пробное уведомление в собственный Telegram по согласованию | Доставка подтверждена отдельно от расчёта правила; дубликатов нет |
| Первые 48 часов | Наблюдать ошибки/429, возраст данных, длительность цикла и БД | Обход укладывается в расписание, UI отвечает во время компактизации, нет множественных сборщиков |

Параметры для проверки (значения задаются после официального анонса, это не готовый `.env`):

```ini
MARKET_SNAPSHOT_ENABLED=true
MARKET_SNAPSHOT_LEAGUE_START=<подтверждённый ISO-8601 UTC нового сезона>
MARKET_SNAPSHOT_EARLY_INTERVAL_MINUTES=5
MARKET_SNAPSHOT_EARLY_DAYS=2
MARKET_SNAPSHOT_INTERVAL_MINUTES=15
MARKET_SNAPSHOT_LEAGUE_CHECK_MINUTES=10
PUBLIC_CANONICAL_ORIGIN=<HTTPS origin интерфейса>
PUBLIC_API_ORIGIN=<HTTPS origin API>
APP_BASE_URL=<доверенный HTTPS URL>
```

`MARKET_SNAPSHOT_LEAGUE` не фиксирует лигу: текущий selector намеренно выбирает первую подходящую challenge-лигу. Для CLI `market-snapshots --league` лига задана явно. Не подменять это предположением о pinning фонового сервиса.

## Проверки и границы

Исходная рабочая копия: `231 passed in 4.05s`. Первый запуск в Windows sandbox завис до обработки API на `socket._fallback_socketpair`; вне sandbox тот же набор прошёл. Это ограничение среды, не доказанный дефект приложения.

Кандидат `0.2.111`: **249 passed in 4.58s**, `compileall mcp_server.py app`, `node --check` для `app.js` и `i18n.js`, `git diff --check` прошли. Добавлено 18 регрессионных случаев. Проверены сохранение signed change в SQLite, HC-фильтрация, работа компактизации в другом потоке, cooldown после rate limit, trusted email origin и Secure cookie, включая вход и подтверждение почты через TestClient.

Production deploy, изменение реальных `.env`/БД, реальные письма и Telegram не выполнялись. Следующий сезон, новые рецепты, новые классы основ и текущая мета требуют проверки после официальных данных; старые allowlist и приоритеты автоматически расширять нельзя.
